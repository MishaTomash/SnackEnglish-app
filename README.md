# 🍪 SnackEnglish

Telegram Mini App для вивчення англійської через короткі сюжетні уроки. Користувач проходить історії рівнів A1–C2 разом із маскотом-печивком Снекі: розмовляє з персонажами в кав'ярні чи готелі, слухає озвучені фрази, вимовляє їх уголос і змагається з друзями в дуелях у реальному часі.

**600+ користувачів** · React 19 · TypeScript · Express 5 · MongoDB · Socket.IO

---

## Що вміє застосунок

**Навчання.** Контент побудований як дерево: рівень → розділ → урок → кроки. Уроки відкриваються по черзі на мапі, а кожен урок складається з кроків десяти типів, від діалогу з персонажем до сюжетного вибору з власною гілкою кроків.

**Голос.** Крок вимови записує голос через MediaRecorder, зупиняється після паузи і відправляє запис на сервер, де його розпізнає Whisper через Groq з автоматичним переходом на OpenAI при збої. Англійські фрази в уроках озвучуються через OpenAI TTS: у кожного мовця свій голос, а інтонація залежить від емоції репліки.

**Утримання.** Серія днів із «днем на порятунок», денна ціль і денний ліміт нових уроків, тижневий рейтинг з автоматичним підбиттям підсумків щонеділі, друзі та реферальний бонус, який нараховується лише після першого пройденого уроку друга.

**Дуелі.** Три режими гри 1×1 на Socket.IO. Сервер повністю керує станом матчу і не надсилає клієнту правильну відповідь до кінця раунду.

**Адмін-панель.** Візуальний редактор уроків з прев'ю будь-якого кроку, розсилки, керування користувачами, налаштування лімітів і озвучки, сповіщення адміну в Telegram про падіння сервера та помилки cron.

## Архітектура

```
Telegram ──▶ Mini App (React, Vite)          Telegram ──▶ Бот (Telegraf)
                 │  initData у Authorization                 │
                 ▼                                           ▼
         Express 5 REST API ◀──────────── спільний процес ───┘
          │        │        │
          │        │        └── Socket.IO /duels ── адаптери ігор
          │        └── cron: серії, рейтинг, нагадування, озвучка
          ▼
       MongoDB (Mongoose)        Groq / OpenAI (розпізнавання, TTS)
```

Фронтенд організований за Feature-Sliced Design (`app`, `pages`, `widgets`, `features`, `entities`, `shared`), стан зберігається в Zustand.

## Технічні рішення

### Рушій уроків на 10 типів кроків

Урок — це масив кроків у JSON, і кожен тип має власний React-компонент у `src/features/lesson-engine/steps/`. Формат описаний у `src/entities/story/types.ts` і дзеркально перевіряється на сервері в `storyContentValidator.ts`, тому адмінка не дасть зберегти урок з помилкою, а помилку покаже на конкретному кроці.

| Тип        | Що робить                                                         |
| ---------- | ----------------------------------------------------------------- |
| `scene`    | Опис сцени, англійські слова можна натиснути й послухати          |
| `dialogue` | Репліки Снекі, користувача й персонажа уроку, кожен своїм голосом |
| `cards`    | Картки нових слів                                                 |
| `quiz`     | Питання з варіантами і поясненням                                 |
| `listen`   | Прослухати фразу й обрати почуте                                  |
| `reply`    | Обрати відповідь на репліку                                       |
| `build`    | Скласти речення зі слів                                           |
| `voice`    | Вимовити фразу вголос                                             |
| `choice`   | Сюжетний вибір з гілкою кроків до трьох рівнів                    |
| `event`    | Візуальна подія: спалах, тремтіння, дощ                           |

### Дуелі як адаптери

Кожен режим реалізує спільний інтерфейс `DuelGameAdapter` з методами `generateRound`, `submitAnswer` і `isMatchOver`, тож новий режим підключається одним класом без змін у коді кімнат і сокетів. Сервіс кімнат окремо закриває граничні випадки: третього гравця, перезапис чужої кімнати, відповіді в паузі між раундами, покинуті кімнати й таймери після від'єднання.

### Авторизація через Telegram initData

Кожен HTTP-запит і підключення до сокета дуелей перевіряється за підписом `initData` (HMAC-SHA256 від токена бота) з обмеженням давності `auth_date`. Тестовий вхід без Telegram працює лише локально з явним прапорцем і ніколи при `NODE_ENV=production`.

### Міграція користувачів зі старої версії

Перша версія SnackEnglish була звичайним ботом з іншою моделлю даних. Скрипт `backend/scripts/import-users.mjs` переніс користувачів у нову базу: рівень, накопичені бали, кількість вивчених слів, реферальні зв'язки і серію (лише для тих, хто був активний останні два дні). Скрипт має пробний режим без запису, лише читає стару базу, не перезаписує наявних користувачів і безпечно запускається повторно.

### Деплой з автовідкатом

`backend/scripts/deploy.sh` перевіряє `.env` на сервері, робить бекап бази, збирає фронтенд і бекенд у тимчасові папки, поки працює попередня версія, підміняє збірку і перезапускає PM2. Якщо сервер не відповідає на `/health` протягом 30 секунд, скрипт сам повертає попередню версію.

## Локальний запуск

```bash
git clone https://github.com/MishaTomash/SnackEnglish-app.git
cd SnackEnglish-app

npm install
cp .env.example .env

cd backend
npm install
cp .env.example .env    # BOT_TOKEN, MONGODB_URI, VITE_APP_URL, VITE_ADMIN_ID
                        # для входу без Telegram: ALLOW_DEV_AUTH=true

npm run dev             # бекенд: http://localhost:3000
cd .. && npm run dev    # фронтенд: http://localhost:5173
```

Telegram відкриває Mini App лише через HTTPS, тому для перевірки в самому Telegram потрібен тунель, наприклад `npx cloudflared tunnel --url http://localhost:5173`.
